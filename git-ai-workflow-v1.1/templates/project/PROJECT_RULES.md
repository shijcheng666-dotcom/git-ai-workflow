## 跨 Agent 开工

1. 各软件打开同一个真实项目目录，轮流操作。对话、软件记忆不视为自动共享。
2. 每次新会话或接力，先读本文件、STATE.md，再按需读取相关知识与来源材料；检查仓库根目录、分支、Git 状态、暂存区及最近记录。
3. 汇报应依据文件或实际检查，没有记录则说明没有记录；用户确认、分析推断和历史提案必须区分。
4. 来源不明或冲突的改动先保护、确认，不覆盖、还原或顺带提交。使用最新明确的用户要求，规则冲突先说明。
5. 其他软件可能有未保存的缓冲区或后台任务；切换前由用户确认保存并停止编辑，新软件加载最新文件。
6. AGENTS.md 是通用短入口，本文件是完整规则；必须实际读取指向的内容。每个工具首次接入先做只读核验，核对路径、读取来源与 Git 状态；显式读取成功不等于自动加载已验证。加载失败可显式读取降级，不默认复制正文或建立符号链接。

## 版本权限与安全

- 用户授权：AI 可自动保存本项目必要的本地恢复检查点；只有用户明确验收对应范围后才能标为验收版本。上传、推送、发布、删除和破坏性恢复另行确认。
- 大改前、重要中间阶段和交接前按需保存，不为每个微小动作提交，不制造空提交。检查点可包含尚未通过检查的本轮工作，但必须明确未验收和风险。
- 只保存明确归属且适合入库的文件，逐项检查后暂存；暂存区有不明内容时暂停提交，不用全量暂存代替范围检查。
- 不擅自修改 Git 全局配置或伪造提交身份；身份缺失先确认。
- 提交信息用中文，区分“检查点／修改／验收／记录”；验收可采用用户确认后的本地附注标签，不能移动既有标签或把未测试项说成通过。
- 不手工编辑 .git，不默认硬重置、清理、强制覆盖、amend、改写历史或自动 stash。
- 恢复先保护所有必要当前内容，再取候选到新位置比较；替换当前入口必须确认目标和范围，验证保护有效，再恢复并建立新记录。
- 本地 Git 不是独立备份，也不保护未纳入的文件。

## 文件与知识规范

- 现有路径优先保留；项目工作文件固定名称，不每次另存。正式交付快照按需放 releases/，说明其来源版本。
- 原始材料保留原件。敏感资料、凭据和不适合入库的大文件按实际范围排除；.gitignore 不会清除已跟踪文件或历史。
- 不推送 Git 不等于 AI 数据不联网。读取敏感资料前先确认该工具的模型请求、索引与留存是否获准；未知时不读取敏感原文，改用获准的脱敏资料。工具内检查点只是补充，不视为跨 Agent 的完整版本历史。
- STATE.md 是唯一当前状态与交接入口；不另建重复进度索引。更新在阶段完成、任务切换、重要决定或交接时触发，不为每个微调重写。
- knowledge/ 按主题增量整理：来源、事实、推断、待验证项、已确认决策分清。研究结论不超过证据范围。
- 关键决定及否决原因记入 knowledge/DECISIONS.md；被替代的决定注明失效与新决定编号，不让矛盾决定同时有效。
- 不全量归档聊天，不自动删除旧知识、不把材料放进全局记忆。工具专属缓存不作为项目权威来源。
- 规则变更、退役或重要口径替换先说明原因与影响，获得用户确认；新软件原生规则仅指向本文件，不复制正文。

## 检查与验收

- HTML：【需要实际查看的页面、设备、打印和交互；内容／数字／来源核对方法】。
- 软件：【启动命令、相关测试、构建、禁止影响的外部系统】。
- 无法实际验证时列明具体未验证项；静态检查、打开预览与用户确认不等于全部测试通过。
- 用户验收仅覆盖明确查看的版本和范围；验收后发生相关变化须重新确认。
- 每轮结果汇报：改了什么、检查证据、未验证项、版本标识、下一步。把结果交付给用户，项目记录不能替代正常答复。
- 分别记录三种状态：已留档（实际提交及覆盖范围）、AI 检查（通过／部分通过／失败／未检查，注明依据）、用户验收（已验收范围／待验收）。这些是独立维度，不因任一状态成立而自动推导其他状态。后续改动可能使旧检查与验收不再覆盖当前文件。

## 正式交付与归档

- 交付形式：【HTML／PDF／软件包／其他，按实际填写】。
- 交付前说明入口、支持范围、依赖和已知问题；正式快照与源文件版本建立关联。
- 项目结束先逻辑归档，保留原路径与历史。搬迁、共享、线上发布、独立备份按公司要求另行确认。
