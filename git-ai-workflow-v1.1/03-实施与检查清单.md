# 实施与检查清单

## 首次接入，AI 应完成的检查

1. 确认真实目录、项目入口和软件对该目录的读写能力；记录完整路径，不能只核对文件夹名。
2. 检查 Git 可用性及当前／父目录仓库边界。已有仓库则复用；出现嵌套或父仓库不明确时先确认。
3. 阅读已有项目规则；核对占位符、文件名、材料来源和验收要求，不默认搬迁目录。
4. 在提交前识别未跟踪文件、已跟踪文件的改动、暂存区和敏感材料。忽略规则不自动移除已经跟踪的文件。
5. 检查当前身份是否可用于提交；不修改全局 Git 配置。身份缺失时先确认；可经明确授权采用单次提交身份参数或仅项目配置，不编造用户邮箱。
6. 只按明确清单暂存；暂存区非空且来源不明时，不把已有暂存内容顺带提交，也不擅自重置暂存区。
7. 创建第一次恢复检查点，检查提交实际包含的文件及最终状态。
8. 在用户指定的下一软件中测试接力。不能仅凭模板存在就宣称三种软件接入成功。

以下命令只是 AI 的检查参考，由 AI 在对应项目目录执行，用户无需背诵：

```text
git --version
git rev-parse --show-toplevel
git status --short --branch
git diff --stat
git diff --cached --stat
git log -5 --oneline
```

空仓库没有提交，`git log` 报告无提交并不代表项目损坏。Git 状态只描述磁盘文件，不包含编辑器中尚未保存的内容。

## v1.1 首次工具接入补充

- 通用入口：AGENTS.md 放在项目根目录，详细规则保持单一来源。已有 AGENTS.md 不覆盖；已有项目规则可复用，但入口与提示词要指向真实位置。
- TRAE：按当前界面找到“设置 → 规则／规则与记忆 → 导入设置”，核对“将 AGENTS.md 包含在上下文中”。界面和能力可能因版本或地区不同；找不到时使用显式读取，不猜配置路径。无须为了本方案同时开启 CLAUDE.md 导入。
- Antigravity：当前官方文档支持根目录 AGENTS.md；在用户安装版本中核验。不要照搬 TRAE 的 YAML 属性或把 @filename 当成通用内联语法。
- Aime：采用显式读取入口的可靠路径，本包未验证原生自动加载。若软件自动生成项目记忆，避免另建重复当前进度；共享入口仍需明确。
- 首次只读核验：使用场景 12，比较实际路径、当前目标、具体约束与 Git 状态。记录在 STATE.md，不创建另一张重复登记表。不以模型自称“已加载”替代文件读取、软件加载列表等证据。
- 数据边界：先核查模型请求、索引和留存政策及公司允许范围。Git ignore 不会自动禁止 AI 读取或上传，不推送仓库不代表素材没有联网。未确认前只用非敏感试点资料。
- 三种状态独立记录：留档范围、AI 检查及证据、用户明确验收范围；允许“已留档但检查失败”“用户接受布局但打印未测”。
- 工具内检查点仅作为补充。切换前核对项目 Git，不使用旧会话一键撤销去覆盖其他 Agent 后续工作。

## Git 保存约定

- 普通恢复提交：`检查点：调整报告结构前`、`检查点：交接，布局待检查`。
- 改动记录：`修改：修正图表标签并保留原结论`。
- 验收提交：`验收：确认研究报告的结构与文案`，只能在用户确认对应范围后使用。
- 验收若恰好落在已有检查点，可由 AI 创建不重复的本地附注标签，如 `accepted-20261026-01`，注释写中文验收范围与未验证项。标签只是引用，不复制文件，也不代表所有内容都通过测试。
- 默认不创建额外分支，不修改旧提交、不强制移动标签、不推送。
- 本方案仅授权本项目必要的本地检查点与确认后的验收标记。外部发布、敏感内容留存及破坏性恢复不在授权范围。
- 需要在 STATE.md 记录验收提交时，先建立对应提交或标签，再更新状态并另存一次状态记录；不要要求文件记录包含它自己的最终提交哈希，也不要为此反复 amend。
- “验收提交／标签指向产物状态”和“交接记录最后一次提交”可以不同，分别说明，避免误解。

## 敏感材料与文件大小

Git 历史会保留旧内容。删除现文件、加入 .gitignore 都不意味着旧版本已经消失。

默认不能自动入库：密钥、登录凭据、含可识别个人信息的逐字稿／样本名单、未获准留存的内部资料。是否可在本地存放与是否可入 Git 是不同授权。

材料可按允许的方式保存在本项目受控位置并排除 Git，知识记录只引用脱敏编号和必要摘要。不入 Git 的文件不能靠 Git 恢复，必须有其他合规备份。排除规则应按实际文件准确配置并测试，不把所有材料目录一概忽略，也不认为模板 .gitignore 是敏感扫描工具。

大型视频、录音、数据包和 Office 二进制文件可以版本化，但容易增大仓库、难以逐行比较。优先保存路径、来源和小型摘要；本地保管或其他备份方式须遵守公司规则。不默认引入 Git LFS 或远程服务。

软件项目的依赖目录、构建产物可忽略；依赖锁文件通常保留。重建不能产生的配置、资源或数据不能因为名字像输出就删掉或忽略。

## HTML 报告验收

- 内容：标题、段落、图表数字与来源没有误删、截断、擅自改写；研究推断与事实保持区别。
- 资源：CSS、脚本、图片和本地链接有效；恢复旧 HTML 时同步核对配套资源。
- 显示：实际打开页面检查关键章节、桌面布局；如果要求移动端或打印，再分别检查。
- 交互：导航、展开、筛选等本轮涉及功能可用；静态检查不能替代实际运行。
- 交付：入口明确，外部依赖、离线可用性与支持范围说明清楚。

AI 没有浏览器操作或截图检查能力时，说明具体未验证项并让用户查看，不把打开预览工具当成完成全部视觉验证。用户验收只覆盖其明确确认的范围。

软件项目另设与改动相关的测试、构建和启动检查，记录命令、结果、环境与未测试项。不能把“测试失败但已保存检查点”说成已完成验收。

## 安全恢复

默认先取候选历史内容到新的对比目录，不改当前入口。跨多个文件时，候选快照须包含所需资源；恢复旧版软件也需核对依赖和配置。

恢复当前入口前必须：

1. 明确恢复目标与范围，并获得用户同意。
2. 保护当前工作：已提交、未提交、未跟踪、已暂存内容，以及 Git 未管理的必要资源。Git 提交只能保护纳入提交的部分。
3. 验证保护结果可读、覆盖范围完整；敏感材料不得因“备份”而被意外提交。
4. 恢复已确认范围，保留其他改动，再检查、记录新提交。

禁止默认使用 `git reset --hard`、`git clean`、强制检出、重写历史或盲目 stash。stash 不保证包含全部未跟踪或忽略文件，也不是独立备份。无法安全保护时停止覆盖步骤，说明缺口。

## 最小试点测试

建议先用一次性、非敏感项目完成以下步骤，再套用真实报告：

| 步骤 | 可检查证据 | 判定标准 |
|---|---|---|
| Agent A 建立检查点 | 提交标识、文件清单、Git 状态 | 预期文件留档，不混入敏感或无关文件 |
| 修改一段文字 | 文件差异、页面预览 | 只改指定范围 |
| 停止 A，Agent B 接力 | 真实路径、分支、状态、读取来源 | B 能辨认当前版本和未提交改动 |
| 未提交时交接一次 | 状态说明和 B 的检查结果 | 不擅自丢弃、覆盖或提交来源不明内容 |
| 提取旧版到对比位置 | 候选文件与资源、当前文件状态 | 旧版可查看，当前工作未受影响 |
| 用户确认后验收 | 验收范围、提交或标签 | 没有把未验收／未测试项写成通过 |

这些是建议执行的实际试点，不代表本模板已经在三种软件中实测通过。

v1.1 增加入口读取核验：分别在 Aime、TRAE、Antigravity 的新会话执行场景 12，先不修改。模型能在显式请求后读到文件，只证明显式路径成功；自动加载要靠工具提供的加载证据或专门测试核验。改规则后优先开新会话。日常接力仍保留显式启动指令。

首次测试无需真实敏感数据，不要求 Agent 安装新软件、访问外部服务或操作用户已有项目。若进行模拟测试，必须注明是同一执行环境的串行模拟，不是三个客户端实测。

## 结束项目与维护

优先逻辑归档：保留原路径，在 STATE.md 和项目清单标记结束。仅在确有需要时，经用户确认移动整个项目；之后验证 .git 历史、相对／绝对链接、软件打开路径与资源。

维护按事件触发：换阶段、入口失效、记录冲突或明显臃肿。没有“每 30 轮必须换会话”或“每周必须全量重写”的强制规则。

## 与旧提示词的取舍

| 旧做法 | 本方案 |
|---|---|
| PROJECT_RULES + INDEX + context | 保留稳定规则；STATE 合并状态与接力；knowledge 按需记录 |
| 交付物每次按日期另存 | 工作文件固定名称，Git 保留历史；正式交付才按需快照 |
| 规则写入后跨工具自动生效 | 接力指令明确读取；原生规则指针可选，生效需核验 |
| 新结论直接覆盖旧结论 | 当前事实更新，关键决定保留依据与替代关系 |
| 固定会话轮数、索引行数 | 状态应简短，按实际信息量和偏差维护，不机械按轮数 |
| 全量原材料整理、周期性全量维护 | 先建立入口，按任务增量整理，不无故重写全部材料 |
