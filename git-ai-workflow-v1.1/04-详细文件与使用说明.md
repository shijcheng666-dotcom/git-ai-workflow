# 详细文件与使用说明

## 1. 先区分三个位置

- **资料包目录**：本次交付的说明、提示词和空模板。它不是实际项目，不应在里面写报告或初始化试点仓库。
- **项目目录**：HTML、图片、源码和项目规则实际放置的位置。三个 Agent 都打开这一真实目录。
- **项目集合目录**：可选，放多个项目文件夹和一份登记清单，不在集合根目录另建一个大仓库。

```text
D:\AI-Workflow\git-ai-workflow-v1.1\    资料包，供 AI 参考
D:\AI-Projects\
  PROJECTS.md                          可选项目清单
  项目A\                              一个真实项目、一个 Git 仓库
    AGENTS.md
    PROJECT_RULES.md
    STATE.md
    knowledge\DECISIONS.md
    report.html                        保留已有入口，不强制改名
    images\
    .gitignore
    .git\
  项目B\                              另一个独立项目
```

以上是示例路径，不代表已经创建。已有 Aime 项目目录可以继续用，不必搬到示例位置。

## 3. 项目中的文件谁来维护

| 文件 | AI 负责什么 | 你负责什么 | 何时更新 |
|---|---|---|---|
| AGENTS.md | 维护简短入口及真实指针 | 重要边界变化时确认 | 首次接入或入口变化 |
| PROJECT_RULES.md | 把明确要求整理成稳定规则，未知项标待确认 | 确认目标、边界和验收要求 | 有实质规则变化时 |
| STATE.md | 记录入口、阶段、版本、未完成项和三种状态 | 核对关键状态，纠正误记 | 阶段结束、交接、重要变化 |
| DECISIONS.md | 记录决定、依据、否决原因和替代关系 | 决定取舍，不让 AI 替你确认 | 有值得保留的关键取舍时 |
| 主题知识文件 | 来源、事实、分析和局限分开整理 | 核对研究结论及证据 | 有新材料或有效发现时 |
| .gitignore | 识别缓存、秘密、大文件和可再生输出，测试匹配范围 | 确认资料是否允许留存与入库 | 文件类别或技术环境变化 |
| PROJECTS.md | 登记项目位置与状态 | 决定建立、结束、搬迁项目 | 项目生命周期变化 |

你可以一直用自然语言交流，无须手动编辑这些文件。模板约定是协作要求，不是所有软件强制执行的安全机制。

## 4. 首次接入：实际操作顺序

1. 选一个非敏感的小项目。在软件中打开其真实文件夹，不只打开单个 HTML。已有目录可以保留。
2. 将 `00-从这里开始.md` 中的初始化指令发给 AI，填写项目路径和本包路径。AI 只访问授权范围；读不到包就提供相关附件或最小目录权限。
3. AI 先检查项目和 Git，报告准备合并哪些文件、哪些不入 Git、是否存在父仓库或未知改动。你确认最小接入方案。
4. 若 Git 未安装，由 AI 给出最小安装方案，经你确认后处理；不把可执行程序混入资料包。Git 已装但身份缺失时，确认真实身份，不冒用或修改全局设置。
5. AI 建立／合并规则、状态和入口，不覆盖原结构；创建必要本地检查点，并说明哪些文件受到保护，哪些没有。
6. 让 AI 展示项目入口与状态摘要。无需你阅读所有管理文件，但重点核对目标、不允许修改的内容、敏感资料边界和验收方式。

首次接入结果不是报告验收。没有检查视觉、打印或软件功能，就必须保留未验证状态。

## 5. 每个软件首次接入

| 软件 | 操作 | 怎样判断接上了 |
|---|---|---|
| Aime | 打开／授权同一项目，显式让 AI 读 AGENTS、规则和状态 | 真实路径一致，读到具体规则，能辨认当前入口与改动 |
| TRAE | 打开同一目录；检查设置中的 AGENTS.md 上下文导入开关 | 开关与版本已核对，执行场景 12 后来源和状态正确 |
| Antigravity | 打开同一目录；核对安装版本对 AGENTS.md 的支持 | 实际读取证据和状态正确；自动加载未测则注明未测 |

官方文档不等于你的安装版本实测。界面菜单可能不同；找不到开关时先显式读取，别创建三套完整规则。

在新工具先发送：

```text
本轮只核验接入，不改文件、不提交，也不读敏感材料。
请读取项目 AGENTS.md 及其指向的规则和 STATE.md，检查 Git。
告诉我真实目录、当前入口、一条具体约束、未完成任务和未提交内容。
注明读取来源；显式读取成功不等于自动加载已验证。
```

核对无误后再给任务。不需要把完整资料包再次导入每个软件；项目内入口与记录已经承载日常协作。若工具不能读取项目文件或不能执行 Git，它只能做讨论／建议，文件操作留给有权限的 Agent，不伪装已经修改或提交。

首次结果由 AI 记录在 STATE 的工具登记中。登记不存在账号和密钥；只读检查不证明写权限已经验证。

## 6. 日常流程：用一个 HTML 修改案例说明

### 开工

```text
按项目规则接力。本轮只调整第二章图表和文字的对应排版。
保留研究结论、图表数字、其他章节和导航。
先读入口与状态，检查 Git，必要时留检查点，再做小范围修改。
```

AI 应确认入口和已有改动，保护可归属的当前状态后修改，不借机重写全文。

### 看结果

AI 提供预览并简短报告，例如：

```text
留档：修改前检查点 abc1234；report.html 和 images/chart.png 已入库。
AI 检查：资源链接通过；实际页面布局待用户查看；打印未测试。
用户验收：待验收。
```

这只是格式示例，不是实际提交。你看到布局不合适就继续提调整；没看到效果前不要让它标成验收。

### 验收

```text
我确认刚才查看的第二章桌面排版可以验收，结论和数字没有问题。
打印效果未检查，不纳入此次验收。请记录对应版本。
```

AI 核对查看后是否又改动，保存对应版本或标签，再更新状态。验收不限于全报告，可以只验收你实际查看的章节或功能。

### 收工与换 Agent

```text
本轮收工，准备换 TRAE。
保存必要检查点，更新状态和未验证项，给我一段接力说明。
```

确认 Aime 任务已结束、文件已保存；旧编辑器未保存的缓冲区不能再次覆盖新文件。TRAE 打开同一路径，加载最新文件，读取状态后继续。两软件可以都开着，但不要同时让它们修改或运行会改文件的命令。

## 7. 故障和旧版恢复

```text
报告改完后白屏。我想找回上一次正常显示的版本。
先查历史、保护当前工作，将候选旧版及必要资源提取到新位置比较。
不要直接覆盖当前入口，也不要一键回退整个项目。
```

你看过候选后，再明确：“恢复这个候选的第二章与配套资源，其他章节保留。”AI 说明影响、确认保护完整，再恢复指定范围并留新版本。需要恢复整项目则另行明确范围。

当前文件受损且无法恢复时，不能把找回部分文件说成全面修复。没纳入 Git 的材料、未保存缓冲区及外部数据不保证找回。

## 8. 软件开发项目有什么不同

沿用原来的源码结构，不强制套 work/ 目录。项目规则填写启动、测试、构建和核心功能的检查方式；状态记录缺失环境及测试失败。

你仍用自然语言：“完成这个功能，按规则留检查点，运行相关测试，告诉我实际结果。”在你验收之前不标成验收版本。以后确需并行实现或独立试验，再按任务建立 worktree；不用给每个软件固定一个分支。

## 9. 多项目如何登记

一个项目先不建总清单也能工作。项目多了，可以让 AI 使用集合模板登记你明确提供的项目路径，不扫描全盘，不把总目录变成大仓库。

```text
请在【项目集合目录】建立或更新 PROJECTS.md。
登记这些项目：【名称、真实路径、状态】。
只做登记，不移动目录、不复制项目，不建立集合级 Git 仓库。
```

结束项目优先在原地标“已归档”，不用强制搬进 archives。移动目录、共享资料、发布和独立备份另行确认。

## 10. 从 v1.0 升级

如果还没在真实项目套用 v1.0，直接使用 v1.1 即可。若已经套用，使用提示词场景 13，先读旧规则和 Git 状态，再增量合并。

保留原目标、特殊规则、来源与安全边界；不重置 STATE、不覆盖已有 AGENTS、不重建仓库。不批量升级所有项目，先升级一个并测试。

资料包原版仍保留在本次工作区 `artifacts/git-ai-workflow/` 及 v1.0 压缩包中；v1.1 在独立目录，不会自动影响已接入项目。

## 11. 常见误区

| 想法 | 实际边界 |
|---|---|
| 每次要发完整提示词 | 初始化后通常用一句启动语即可 |
| 建 Git 就能自动避免改坏 | Git 留历史，质量仍靠预览和测试 |
| 文件叫 AGENTS 就必然自动读 | 需核对软件支持、设置和版本，保留显式读取降级 |
| 一个工具撤销能安全跨工具回退 | 可能覆盖另一工具的后续工作，优先公共 Git 历史并保护当前状态 |
| 检查点一定是可用版 | 可以是未验收或检查失败的恢复点 |
| 每次都要清空未提交改动 | 不强求干净；先辨认并记录，不能为了干净丢工作 |
| .gitignore 保护资料不被 AI 读取 | 它只控制 Git 跟踪，不控制模型请求和索引 |
| 我不用学命令，所以不用核对结果 | 你仍需核对目标、预览、关键决定与验收范围 |
