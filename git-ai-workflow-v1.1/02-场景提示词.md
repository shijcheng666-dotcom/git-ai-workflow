# 场景提示词

使用方式：只发送当前场景的一段，替换【占位符】。初始化完成后，以项目规则文件为统一来源，不必反复发送本手册。

## 1. 首次建立项目或给旧项目接入工作流

```text
请为【项目名称／目标】建立本地 Git 协作工作流。
项目真实目录：【完整路径】。
配套模板所在位置：【解压后的 templates/project 完整路径】。

先只检查：当前目录、Git 是否可用、现有文件结构、当前或父目录是否已有仓库、Git 状态与已有项目规则。不要先移动、改名、删除文件或重复初始化仓库。
若模板无法读取，告诉我，不要假装已套用。

给出最小接入清单：保留哪些现有结构、准备新增哪些文件、敏感或大文件如何处理、第一次检查点覆盖哪些文件。重要信息缺失时，只问影响接入的关键问题。
经我确认后，再建立或合并 AGENTS.md、PROJECT_RULES.md、STATE.md、knowledge/DECISIONS.md 和适合当前项目的 .gitignore。AGENTS.md 只作为短入口与关键安全提醒，详细规则只维护一份。已有同类文件尽量复用，入口改为指向真实文件，不另建重复事实源；不得原样覆盖已有规则。
检查当前工具的规则加载、权限与数据处理边界，不假定 AGENTS.md 自动生效，不照搬其他工具的导入语法。敏感材料未经允许不读取、不索引、不入库。

我授权你在本项目自动创建必要的本地恢复检查点，但只有我明确确认某个结果后才能标记为验收版本。只提交已检查、明确属于本项目且适合保存的文件；不得上传、推送或发布，不得丢弃已有改动。
首次提交前检查身份、暂存区、敏感内容和忽略规则。身份缺失时向我确认，不伪造、不修改 Git 全局配置。已有暂存内容或归属不明改动先保护并确认。

完成后说明：真实目录、入口文件、仓库状态、检查点标识及检查范围、未验证项，以及下一次开工该发什么。
```

## 2. 开工与跨 Agent 接力

```text
请在当前项目接力。本轮目标：【任务】。
先确认真实工作目录和仓库根目录，显式读取 AGENTS.md、PROJECT_RULES.md、STATE.md（如入口复用既有文件，按真实指针读取），再按任务读取相关知识和来源材料；不要全量加载无关文件。入口缺失则用现有规则降级接力并说明，不凭空生成已确认规则。
检查当前分支、Git 状态、暂存区和最近提交。已有改动先辨认来源；来源不明或与任务冲突时暂停相关修改，不擅自覆盖、还原或提交。
用简短说明告诉我：当前进度与入口、必须遵守的决策、本轮准备做什么及如何检查。注明来源；没有记录就说没有记录。
若目标清楚且没有关键冲突，直接按规则推进；若需我做重要取舍，先确认。不要仅凭旧会话记忆操作。
```

## 3. 修改 HTML 报告或其他产物

```text
请修改【文件／入口】：【具体改动】。
必须保留：【不允许改变的内容、布局或交互】。

按项目规则先检查已有改动；必要时为已保存、可归属的当前状态建立恢复检查点，再做最小修改。工作文件保持固定名称，不为每次尝试复制一整套版本。
不要借本轮任务重构全文、替换技术方案、改写无关结论或清理其他文件。
改完检查差异、内容与资源链接；HTML 按项目要求检查页面、布局和交互。工具不能实际验证的部分要明确说明，不能把文件能读或语法通过说成视觉验收通过。
分别汇报：已留档的检查点及覆盖文件、AI 实际检查及未验证项、用户验收状态，并给我可查看的结果；在我验收前不要标为验收版本。
```

## 4. 软件开发任务

```text
请完成【需求／修复目标】，保留现有项目结构与约定。
先读规则、状态和相关源码，判断根因或实现边界，再做最小修改。按规则保存必要恢复检查点。
运行与改动直接相关的测试或构建；缺少环境、无法运行或检查失败时明确说明，不宣称通过。不要为了测试删除现有数据或影响外部服务。
结束时说明：改动文件、验证命令与结果、未验证项、如何启动或复现。更新必要交接状态，等待我验收。
```

## 5. 验收当前版本

```text
我确认刚才查看的【产物／入口和改动范围】可以作为验收版本。
请先确认我查看之后有没有新增改动；如有会影响验收的变化，先让我重新确认，不扩大我的验收范围。
按项目规则完成已授权范围的本地提交／版本标记，更新 STATE.md，记录提交标识和验收范围；保留仍未验证的内容，不把我的确认替代实际测试结果。
只处理本项目本轮明确归属的文件，检查暂存区，不混入其他人的或无关改动。完成后说明验收标识、剩余事项和仓库状态。不上传、不发布。
```

## 6. 收工与交接

```text
本轮到这里，请准备换会话或换 Agent。
等待当前任务结束并保存文件，检查 Git 状态。对本轮可归属且适合留档的改动按需保存恢复检查点；存在归属不明或不宜入库文件时先保护，不强求工作区全部干净。
更新 STATE.md：当前入口、完成事项、关键未验证项、未提交文件及原因、下一步和下一位 Agent 应读取的文件。
仅把新的有效背景／研究发现归入对应知识文件，来源明确；把值得保留的决定和否决原因写进决策记录。不要重复归档聊天，不虚构我的确认。
状态更新也须留档；汇报最终 Git 状态、检查点标识和仍未提交的内容。给出一段下一位 Agent 可直接使用的简短接力话术。
不要声称退出本会话就已停止其他软件的后台任务；提醒我切换前检查其他软件已停止编辑并保存。
```

## 7. 安全恢复或比较旧版本

```text
当前问题：【现象】。我希望找回：【之前的效果／大致阶段】。
先调查版本历史与差异，不要直接覆盖或丢弃当前工作，不使用硬重置、强制检出或清理命令。
列出最相关的少量候选版本，说明各自范围；先把候选内容恢复到新的对比位置供我查看。保留当前已跟踪、未跟踪、未提交和已暂存的内容及资源，敏感材料按项目规定保护。
我确认候选版本后，说明会替换哪些内容及可能损失哪些后续改动；获得明确同意并验证保护副本有效后，才在工作入口恢复指定范围。不要一键回退整个项目，除非我明确要求并确认范围。
恢复后检查和记录一个新的本地版本，保留原历史，说明恢复的内容和仍存在的问题。恢复旧文件不等于原问题已修复。
```

## 8. 背景材料与研究发现归档

```text
请整理【本轮素材／指定材料】到当前项目知识中。
先检查已有记录，复用主题文件。保留原始材料，不删除、不改写原件；记录来源位置、日期和必要定位信息。
分开呈现：原始事实／用户原话、分析推断、待验证问题、我已明确确认的决策。结论不能超过证据范围，缺失来源或数据就明确标注。
当前有效内容写进对应主题文件；关键变更及否决原因写入决策记录，并标明替代关系；STATE.md 只保留入口和与当前阶段相关的摘要，不复制研究正文。
不得把敏感原始材料或个人信息自动提交进 Git。结束时说明更新位置、主要变化、待确认项和版本保存状态。
```

## 9. 项目集合登记与结束归档

```text
请更新项目集合清单【PROJECTS.md 完整路径】中的【项目】条目。
核对真实路径、状态、入口和最后更新时间；信息不足就标待确认，不扫描全盘。清单只登记，不复制研究正文或各项目 Git 历史。
若项目结束，先在原目录记录结束状态、正式交付标识、未完成项和保留说明，再把清单标为已归档。
默认只逻辑归档，不移动目录、不删除材料、不建立集合级 Git 仓库。确需搬迁或打包另行给方案并等待我确认，之后验证链接、资源路径、Git 历史和各软件工作区入口。
```

## 10. 按需维护

```text
请检查本项目协作文件是否存在重复、冲突、过时入口和过长状态记录。
优先维护 PROJECT_RULES.md、STATE.md 与当前直接相关的知识文件，不全量重写项目资料。
区分稳定规则、当前状态、来源证据、历史决策；可更新的当前状态原位更新，必要决策保留原因和替代关系。不能仅因记录较旧就删除。
先列出维护清单；规则退役、知识删除或含义变化必须经我确认。不要更改 Git 历史、清理其他 Agent 配置或顺便调整产物。
执行后说明变化和未解决事项，保存本地检查点但不标为产物验收。
```

## 11. 各软件可选的项目规则指针

仅在确认软件当前版本支持项目规则后配置。不创建或覆盖未经核验的原生规则文件。

```text
本项目跨 AI 工具共享。开始任何项目任务前，读取项目根目录 AGENTS.md，按其指针实际读取完整规则与 STATE.md，再按需读取相关材料并检查 Git 状态。遵守最新明确的用户要求；缺失、冲突或无法访问时先说明，不凭历史对话补造。不要在此处复制规则正文。文件引用不等于已读取内容。
```

## 12. 每个工具首次接入的只读核验

```text
本轮只验证接入，不修改文件、不提交、不运行构建或安装，也不访问敏感原文。
请核对当前真实工作目录与仓库根目录，读取 AGENTS.md 及其指向的规则和 STATE.md，检查分支、Git 状态、暂存区和最近提交。
说明你实际读取的文件及其中一条具体约束，当前目标、入口、未完成项和来源不明改动。只有显式读取证据时，不要说自动加载已验证。
报告当前工具与可确认的版本，AGENTS.md 自动加载状态（已核验／未核验）、文件读写授权和数据处理核验状态；未知就写未知。无需读取敏感材料来测试权限。
若加载失败，给出显式读取的降级话术；不要复制规则、创建符号链接或改其他工具的配置。
```

## 13. 已接入 v1.0 的项目增量升级

```text
请将本项目协作方式从 v1.0 增量升级到 v1.1。
新版包路径：【完整路径】。
先阅读新版 05-版本变更与依据.md，再检查现有规则、状态、Git 和工具配置，列出原有能力基线与拟改动。
保留项目已确认规则、来源证据、决策记录和降级路径。保护现有文件，合并而非覆盖；AGENTS.md 已存在时保留其有效规则，仅补充入口。指针必须使用本项目真实相对路径。
只增加通用入口、三种状态记录、工具接入核验与数据处理提醒，不改报告、源码或现有分支。
经我确认后实施，保存必要本地检查点，检查新入口及原有安全恢复、暂存区和敏感材料边界。列明仍需在其他工具中测试的内容，不宣称已全端接入。
```

## 日常最短说法

初始化和验证通过后，日常可简化为：

- 开工：“按项目规则接力，本轮做【任务】。先读状态并检查 Git，再推进。”
- 改稿：“只改【范围】，保留【内容】。必要时先留检查点，改完给我预览和未验证项。”
- 验收：“我验收刚才查看的【范围】，请保存验收版本，不扩大范围。”
- 收工：“按项目规则收工，保存必要检查点、更新状态，给下一位 Agent 接力说明。”
- 故障：“先保护当前工作，找候选旧版本供我比较，不直接覆盖。”
