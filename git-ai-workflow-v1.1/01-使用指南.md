# 本地 Git × 多 Agent 项目协作工作流

适用：HTML 用研报告、研究项目、软件开发；Aime、Trae、Antigravity 等能读写本地文件的 AI。默认同一电脑、同一真实项目目录、轮流接力，不做并行编辑。版本：1.1。

第一次使用请先看 `00-从这里开始.md`；文件用途、逐步操作和完整案例见 `04-详细文件与使用说明.md`。v1.1 增量保留 v1.0 的安全与降级规则，变化见 `05-版本变更与依据.md`。

## 一句话说明

你负责目标、取舍和验收；AI 负责读取项目状态、小步修改、保存恢复检查点、检查结果和交接。Git 保存文件历史，项目记录保存背景与决策，预览或测试检查质量。

## 你平时只需要做什么

1. 新项目：选定项目目录，发送提示词手册中的“首次建立项目”。
2. 开工或换 Agent：在软件里打开同一个目录，发送“开工与接力”，补充本轮任务。
3. 中途修改：直接描述要改什么和不能动什么；AI 按项目规则保存必要检查点。
4. 看过结果满意：发送“验收当前版本”。不满意则继续修改，不必先验收。
5. 收工或换软件：发送“收工与交接”。
6. 改坏了：发送“安全恢复”，描述想恢复到什么效果，不必自己操作 Git。

## 配套文件怎么用

- `02-场景提示词.md`：你按场景发给 AI，不必每次发送全部。
- `03-实施与检查清单.md`：安装、导入、回退、安全和维护的细节。
- `templates/project/`：项目模板；让 AI 按需套用，不要直接覆盖已有文件。
- `templates/collection/PROJECTS.md`：多个项目的登记模板，放在项目总目录；不是每个项目都放一份。

此包只是模板和说明，没有初始化任何实际项目仓库、安装 Skill 或移动材料。占位符必须在使用时填写，不能当成真实项目信息。

## 多项目：集合只登记，各项目独立管理

建议结构，路径和名字可换：

```text
D:\AI-Projects\
  PROJECTS.md               项目清单，不存放研究正文
  浏览器搜索用研\           独立 Git 仓库
  内容报告工具\             独立 Git 仓库
  archives\                 已结束项目，可选
```

不要在集合总目录再初始化一个 Git 仓库，避免无意形成嵌套仓库。优先选本地非自动同步目录；如使用同步盘，必须验证其对隐藏目录和文件锁的行为。不把软件自己的安装目录、缓存目录当作项目根目录。

已有项目如果在 Aime 工作区目录中，可以继续用，不要求搬家。先验证另外两个软件能打开该真实路径。

每个独立项目一个仓库；同一研究项目的多份 HTML 可共用一个仓库。软件开发如果生命周期、权限或发布流程独立于研究项目，另建仓库，通过路径关联，不复制源码。

## 项目内部：只维持三份核心记录

```text
项目目录/
  AGENTS.md                跨工具短入口，不复制全部规则
  PROJECT_RULES.md         稳定规则、目标、边界和验收方式
  STATE.md                 当前状态、入口、待办和交接，保持简短
  knowledge/
    DECISIONS.md           关键决策及否决原因
  materials/               原始材料，按需建立
  knowledge/               背景、研究发现、方法说明，按需新增
  work/                    HTML 工作稿及配套资源，报告项目可用
  releases/                正式交付快照，按需建立
  tmp/                     可再生临时文件，默认不入 Git
  .gitignore               按实际项目设置
  .git/                    Git 自己维护，禁止 AI 手工编辑
```

目录结构是默认建议，不是迁移命令。已有软件项目保留 `src/`、`tests/` 等原结构；已有 HTML 名称和资源路径尽量不改。`STATE.md` 写清真实入口即可。

不再同时维护 INDEX、交接单和状态表三份重复进度。主题知识只在需要时增加；Git 不适合存所有聊天原文。

## 检查点和验收版本不是一回事

| 类型 | 何时保存 | 代表什么 |
|---|---|---|
| 恢复检查点 | 大改前、重要中间阶段、交接前按需 | 文件已留档，可恢复；不代表已通过检查 |
| AI 检查结果 | 每轮修改后检查相关内容 | 单独记录通过／部分通过／失败／未检查及范围；不是用户验收 |
| 验收版本 | 你明确确认具体版本可用后 | 你看过并接受的范围；未验证项仍须列明 |

授权 AI 自动创建本地恢复检查点，不代表授权上传、发布、删除、覆盖他人改动或保存敏感材料。不能把每句对话都提交一次，也不能因没有提交就认定内容没保存到磁盘。

Git 检查点只包含已保存到文件的内容。跨软件编辑前保存文件、等待任务结束；旧编辑器可能保留过时的未保存缓冲区，重新打开或加载最新文件后再编辑。

默认用当前分支接力。普通报告暂不引入分支、worktree、远程仓库或自动化脚本；复杂开发试验出现明确需求时再单独设计。

## 用研资料如何沉淀

- 原始逐字稿、数据和业务素材：保留原件，记录来源和位置，不擅自覆盖。是否入 Git 取决于敏感性、大小和公司要求。
- 研究发现：分清原话、事实、分析推断和用户已确认决策；标注来源位置及局限。未经你确认，不能写成你的结论。
- 当前状态：只写目前有效的事实和下一步，旧进度由 Git 留历史。
- 关键决策：保留理由；推翻旧决策时注明被哪条替代，而不是让两个相互矛盾的决定同时有效。
- 未成功的尝试：只记录有助于避免重试的现象、条件和原因；未查明原因不能编造根因。

## 三种软件如何共享

项目文件、分支和 Git 历史共用；对话、账号、插件、权限和个人记忆不共享。不能承诺三种软件会自动读取同一规则文件。

最低可靠入口是：每次新会话发接力提示词，明确读 `PROJECT_RULES.md` 和 `STATE.md`。如果某软件支持持久项目规则，可加一条指针，不复制规则正文；文件名称、作用域和是否生效需按该软件当前版本核验。

v1.1 增加 `AGENTS.md` 作为通用短入口；正文仍只在 PROJECT_RULES.md 维护。TRAE 官方文档要求开启 AGENTS.md 上下文导入；Antigravity 当前文档列出支持，但安装版本须核验；Aime 本包采用显式读取，不承诺自动加载。原生规则只指向入口，不默认复制或建立符号链接。首次在每个工具中仅做读取与 Git 检查，记录结果，再允许修改。

软件可能新增 `.aime/`、`.trae/` 等文件。先识别其用途：可共享的项目规则可以入 Git，个人设置、缓存和登录信息排除。不盲目清理，也不默认整个目录都忽略。

## 为什么不只靠 Git

Git 不能防止白屏、保证研究结论正确、共享聊天记忆或阻止两个 Agent 互相覆盖。检查与交接仍是必需步骤。

本地仓库不是独立备份。硬盘损坏可能连项目和历史一起丢失。日后可按公司允许的方式备份整个项目，包括 `.git` 和不入 Git 的材料；本方案不默认上传任何地方。

工具内部检查点只能作为补充，不假定可跨 Agent 使用或覆盖全部改动。不推送 Git 也不意味着工具读取的内容不会进入模型请求或索引服务；首次使用敏感材料前须独立核查数据处理设置。无法确认时不读取敏感原文，改用已获准的脱敏资料。

## 先从一个项目开始

先在一份非敏感的小报告或一次性测试项目上走通“修改 → 检查点 → 换 Agent → 恢复到新位置 → 验收”。确认路径和交接可靠，再逐步用于其他项目，不批量改造全部旧项目。
