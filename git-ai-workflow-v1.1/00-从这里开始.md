# 从这里开始：你只需要指挥，AI 负责维护

这是 v1.1 工作流资料包，不是软件、不是 Skill，也不是一个已经建好的项目仓库。无需安装。AI 需要能访问项目和本包目录；权限不允许时，可通过软件的附件方式提供说明，不扩大到全盘授权。

## 第一步：选一个项目

先选一个非敏感的小 HTML 报告试点。让 Aime 打开它原本所在的文件夹，不要复制三份分别给三个 Agent。模板包放在外面即可，不必整个塞进项目。

## 第二步：在项目工作区发送初始化指令

将下面两个路径换成真实路径。`【本包根目录】` 指解压后能直接看到本文件、01／02／03 等文件及 templates 的目录，不是压缩包文件路径。

```text
请为【项目名称】接入本地 Git 与多 Agent 协作工作流 v1.1。
项目真实目录：【项目完整路径】。
工作流资料包：【本包根目录完整路径】。

先阅读包内 01-使用指南.md、03-实施与检查清单.md、05-版本变更与依据.md，并参考 templates/project/。
先检查现有规则、Git、文件结构和敏感资料边界；模板无法读取就说明，不假装已经套用。
给出最小接入清单，经我确认后再建立或合并项目入口、规则、状态和忽略配置。不移动文件，不覆盖旧规则，不读取未经允许的敏感原文。
我授权你自动创建必要的本地恢复检查点；只有我明确验收对应结果后才能标记为验收版本。不上传、不推送、不发布，不丢弃已有改动。
首次接入核对提交身份和暂存区。缺失信息只问关键问题。
完成后说明入口、创建的文件、检查点覆盖范围、未验证项，以及我下次开工该说什么。
```

## 第三步：以后用简短指令

- 开工：“按项目规则接力，本轮做【任务】。读取入口与状态，检查 Git 后推进。”
- 改稿：“只改【范围】，保留【内容】。必要时先留检查点，改完给我预览和三种状态。”
- 验收：“我验收刚才查看的【范围】，请保存对应验收版本。”
- 收工：“按项目规则收工，留检查点、更新状态，给我下一位 Agent 的接力说明。”
- 改坏：“先保护当前工作，提取候选旧版供我比较，不直接覆盖。”

## 第四步：第一次换软件

在旧 Agent 中收工，等任务结束并保存文件。新 Agent 打开同一个完整路径；首次接入先使用 `02-场景提示词.md` 的场景 12 做只读核验，成功后再发任务。TRAE 需要检查 AGENTS.md 导入开关；Aime 明确要求读取；Antigravity 按安装版本核验。不要求学习分支或命令。

## 资料包里先看哪些

| 你的情况 | 看哪里 |
|---|---|
| 不知道怎样开始 | 本文件的初始化指令 |
| 想知道每个文件放哪、谁维护 | 04-详细文件与使用说明.md |
| 需要完整场景话术 | 02-场景提示词.md |
| 给 AI 查实施、安全和测试要求 | 03-实施与检查清单.md |
| 已经用过 v1.0 | 02 中场景 13，增量升级，不覆盖 |
| 想了解新增依据和保留能力 | 05-版本变更与依据.md |

若当前项目不是在本包所在工作区，先打开目标项目再初始化，不要把资料包目录误当成项目目录。本包只证明文件已制作和包内检查结果，不证明你电脑上的三个工具已经接入。
