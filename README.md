# Git 多 Agent 协作工作流

这是一套面向多个 AI Agent 轮流协作的项目管理工作流，重点解决项目文件版本保护、背景接续、规则共享和安全交接。它是文档与模板，不是软件或已安装的 Skill。

## 当前版本

- **v1.1**：当前发布版本，位于 [`git-ai-workflow-v1.1/`](git-ai-workflow-v1.1/README.md)。
- v1.1 增加了 `AGENTS.md` 通用入口、首次接入核验、三种工作状态区分和旧项目增量升级指引。
- v1.0 原始资料在制作时保留；目前没有上传到本仓库。

## 从哪里开始

1. 阅读 [v1.1 快速开始](git-ai-workflow-v1.1/00-从这里开始.md)。
2. 需要整体理解时阅读 [使用指南](git-ai-workflow-v1.1/01-使用指南.md)。
3. 按任务选择 [场景提示词](git-ai-workflow-v1.1/02-场景提示词.md)。
4. 初始化、排障或检查安全边界时参考 [实施与检查清单](git-ai-workflow-v1.1/03-实施与检查清单.md)。
5. 查看每个文件放置方式和维护分工，阅读 [详细文件与使用说明](git-ai-workflow-v1.1/04-详细文件与使用说明.md)。
6. 核对版本变化、依据和验证边界，阅读 [版本变更与依据](git-ai-workflow-v1.1/05-版本变更与依据.md) 与 [交付检查记录](git-ai-workflow-v1.1/06-交付检查记录.md)。

## 使用边界

- 这是**工作流资料仓库**，不是你的实际报告或软件项目仓库。实际项目应各自保存在独立目录并建立自己的本地 Git 仓库。
- 按需把 `templates/` 中的模板合并到实际项目；不要把整套说明文件复制进每个项目，也不要覆盖已有规则。
- 本仓库当前为公开仓库。不要在此提交访谈原文、公司内部材料、凭据或其他不适合公开的信息。
- Git 不会替代页面预览、软件测试或用户验收；留档、AI 检查和用户验收是不同状态。
- 资料说明和模板不保证各 Agent 自动读取或严格执行；首次使用应按指南进行只读核验。

## 版本维护

- 新版本使用独立目录，例如 `git-ai-workflow-v1.2/`，保留已发布版本，避免静默覆盖。
- 更新时记录变更、原因、影响范围和验证结果；检查原有有效安全边界和降级路径是否保留。
- 仅在新版本完成文件检查和说明更新后，将 README 中的“当前版本”指向新版本。
- 本仓库暂未声明开源许可证；公开可见不等于授予复制、修改或再分发许可。
